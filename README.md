# Buddy Owens

**Operations Analyst | Data Reporting · Automation · Applied AI**

I build reporting workflows and small, evidence-led tools that make messy operational
information easier to inspect and use. My work centres on Excel reporting, SQL analysis,
Python automation, data validation, and evaluated AI-assisted pipelines — with explicit
source boundaries, reproducible checks, and clear statements about what is current,
historical, or unknown.

---

## Featured work

### Portfolio Operations Dashboard
An operations dashboard that presents dated evidence for data collection, publishing
activity, and quality checks across my portfolio projects. It helps distinguish a recorded
event, an observation that needs refreshing, and an unknown without presenting the snapshot
as live service health.

`Python · deterministic checks · evidence handling · dashboard design`
[Open the dashboard](https://buddyowens.net/ivy-health/) · [Project Notes](https://buddyowens.net/projects/ivy-health-dashboard/)

### Retail Operations Reporting
An Excel reporting system that turns transaction-level data into reconciled KPIs. Five
layers — intake, working checks, pivot engine, presentation — with fully linked views, no
hardcoded metrics, and a reconciliation layer that has to pass before a number is reported.
Built on a simulated retail dataset, not a live ERP.

`Excel · reporting architecture · reconciliation · KPI definition`
[Project Notes](https://buddyowens.net/projects/retail-operations-reporting/)

### Retail SQL Explorer
A read-only SQLite database with an in-browser Datasette Lite interface over 1,000
simulated retail transaction line items, including KPI and reconciliation views for live
SQL walkthroughs.

`SQL · SQLite · data modelling · KPI validation`
[Live demo](https://wgudataninja.github.io/retail-transactions-sql-explorer/) · [Repository](https://github.com/wguDataNinja/retail-transactions-sql-explorer)

### SilverLeaf Brief
A supervised neighborhood briefing that organizes public updates for SilverLeaf and
northwest St. Johns County into searchable, source-linked information. Publication runs
from reviewed records through a deterministic path; there is no unattended autonomous
publication, and it is not an alert service.

`Python · deterministic publishing · source provenance · editorial review`
[Public briefing](https://wgudataninja.github.io/sjc-intel/) · [Repository](https://github.com/wguDataNinja/sjc-intel)

### WGU Atlas
A catalog research tool for WGU programs and courses: course and program exploration,
catalog history across 108 published editions, a timeline of catalog events, and explicit
data provenance. Official catalog facts, community signals and any labelled LLM-generated
content are kept in separate fields and never mixed.

`Python · Next.js · data validation · catalog versioning · provenance`
[Public site](https://wgudataninja.github.io/wgu-atlas/) · [Repository](https://github.com/wguDataNinja/wgu-atlas)

### WGU Feedback Analyzer
A frozen, published analysis of 1,103 WGU-related Reddit posts across 242 courses, built as
a multi-stage LLM pipeline with frozen development/test splits, prompt snapshots, model
comparison and paired testing. It is a completed historical artifact with reported,
scoped evaluation results — not an active collection system.

`Python · LLM classification · evaluation with frozen splits · deterministic reporting`
[Published snapshot](https://wgudataninja.github.io/WGU-Reddit-Feedback-Analyzer/) · [Repository](https://github.com/wguDataNinja/WGU-Reddit-Feedback-Analyzer)

### Reddit Early Engagement Dynamics
A seven-day observational study of early post visibility on r/AskReddit using 15-minute
listing snapshots — about 27,000 post-segments — with explicit hypotheses, freeze rules and
no backfill. The results are observational and make no causal claim.

`Python · measurement design · collection discipline · analysis`
[Repository](https://github.com/wguDataNinja/reddit-early-dynamics)
